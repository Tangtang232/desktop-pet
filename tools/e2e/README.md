# 真桌面测试

冒烟测试（`npm run smoke`）在一个看不见的窗口里按剧本跑，测不到"系统鼠标点下去到底落到了哪"。这里的脚本在真桌面上、用系统鼠标测，会移动你的鼠标，跑的时候别碰鼠标。只能在 Windows 上跑。

## 拖狗：`drag-real.mjs`

```
$env:PET_E2E='1'; node_modules\electron\dist\electron.exe --inspect=9401 . --remote-debugging-port=9400
node tools/e2e/drag-real.mjs 20          # 拖 20 次，一半停着拖、一半走路时拖
node tools/e2e/drag-real.mjs 20 --eat    # 假装页面自己的"按下"全被吃掉，只靠主进程那一路
```

两种都要 20/20 才算过。改过下面这些地方都要跑一遍：鼠标点穿（`updateInteractive`、`hitTest`）、窗口层级（`desktop-layer.js`）、小窗口的位置、主进程的 `startCursorWatch`。

### 为什么要两路

狗的窗口不抢焦点（点狗时不会把你正在用的程序切走）。代价是：别的程序在前台时，点狗的第一下"按下"有时会被 Chromium 当成激活点击吃掉，页面只收到"松开"，狗就拖不动（2026-11-26 在真机上抓到过）。所以：

- 主进程每 40 毫秒看一次鼠标位置和鼠标键。鼠标在狗身上（页面已切成可点）时按下，主进程告诉页面"按下了"；之后的松开、按着时的位置也都报给页面。
- 页面自己的 `pointerdown` 照收。两路谁先到算谁，300 毫秒内的第二次不算。
- 鼠标不动、狗在动时，页面每 0.1 秒重新判断一次鼠标下面是不是狗（不然狗走到静止的鼠标底下点不着，狗走开了那一块还挡着桌面）。
- 小窗口（写纸条、一起养）开在狗走路那一条的上面；被拖下来盖住狗时，主进程把那块当成"被挡住"。
- 主进程补"按下"之前先问系统：这一下点击会交给谁（`WindowFromPoint`）。交给狗的窗口或桌面才算；开始菜单、弹出菜单、无边框程序、任务栏盖在狗上面时，你在那些地方点一下，狗不会被一起拎起来。`--eat` 模式 20/20 就说明这道检查没把正常的拖狗挡掉。

测试前先看一眼：真鼠标点的是狗所在的位置，狗要露在外面（没被程序窗口盖住），不然点击会落到盖着它的那个程序里。正在养的那只狗如果刚好站在测试狗的位置，点击可能被它接走。

## 拖碗：`bowl-real.mjs`

```
node tools/e2e/bowl-real.mjs 5
```

鼠标移到碗上、按住拖 300 像素、松开，看碗挪过去、落回地上、位置记下来没有。测完把碗放回原处。

两个脚本都会核对鼠标是不是还在刚放的位置：有人同时在动鼠标，那一次不算，自动重测（最多重测 10 次）。

## 出问题时看什么

`%APPDATA%\desktop-pet\diag.log`：页面发现输入异常时写一行（同一种一分钟最多一行），带最近 20 条输入记录。`dom-down-missing` 表示页面自己没收到按下、靠主进程那一路接住了；`press-miss` 表示主进程报了按下，但位置不在狗身上。还会记：`main-error` / `main-rejection`（主进程意外的错）、`renderer-gone` / `renderer-unresponsive`（页面崩了、卡死）、`frame-error`（某一帧出错，一分钟最多记一次）、`gl-lost`（显卡上下文丢了）、`state-restored` / `state-lost` / `state-newer`（存档用了备份、坏了没备份、是新版本写的）。朋友那边出问题时，让他点托盘 →「关于」→「复制诊断信息」发过来，里面有最近 30 行。

## 存档保护：`save-real.mjs`

```
node tools/e2e/save-real.mjs
```

开一个看不见、不联网的测试副本，约 1 分钟：页面脚本跑起来、还没读到存档时连着重载两次，存档里的纸条还在；更新版本写的存档原样留着；写坏的存档用 `.bak` 接着养、坏的改名留底。7 项都要过。拿旧版本的目录跑（`PET_ROOT=<目录>`）能看到旧版本在这里丢存档。

## 朋友视角的全流程：`journey-real.mjs`

```
npm run dist:dir
node tools/e2e/journey-real.mjs
```

用打包好的程序（`dist/win-unpacked`）开两台看不见的"刚装好的电脑"，真连 Supabase，约 1 分钟：第一次打开的提示、托盘菜单、检查新版本、复制诊断信息（不碰真的剪贴板）、发起邀请（还没开始一起养）、对方输码申请、同意后开始一起养、写纸条让狗叼过去、对方收到看完、对方退出（回到等朋友加入）、只有自己时写纸条走本机演示、不邀请了（组散掉）。38 项都要过。会留下两个匿名账号。

## 从 0.1.0 升级：`upgrade-real.mjs`

```
git worktree add --detach <目录> v0.1.0
mklink /J <目录>\node_modules node_modules
npm run dist:dir
$env:PET_OLD='<目录>'; node tools/e2e/upgrade-real.mjs
```

旧版本开两台建两人组，再把一台换成新打的打包版（同一份存档）：还在组里、身份不变、狗的生日和脾气不变、认出已经开始一起养、认领钥匙交上了，旧版那台照常用。11 项都要过。跑完先 `rmdir <目录>\node_modules`（只删链接）再 `git worktree remove`。

## 合养补完（三个人、一个人两台电脑）：`together-real.mjs`

```
node tools/e2e/together-real.mjs
```

自己开四个看不见的测试副本（A、B、C，A 还有第二台电脑 A2），真连 Supabase，不动鼠标，约 8 分钟：加人和审批、邀请码加密存一份、换码、新电脑认领"我是谁"、狗跟着你在用的那台、请人离开的投票、远程看它、远程喂、碗上的气泡、被呼唤时留它一次、退出、最后一个人走了组就散了。跑完把四个副本关掉、临时存档删掉；服务器上的组也跟着散了，只留下几个匿名账号。截图（认领、投票、看看它）在 `tools/out/together/`。

测试里会把几个副本的"键鼠空闲时间"改成固定值，跑的时候你在不在电脑前都不影响结果。

## 两块屏幕

只能在左右挨着的两块屏幕上测：用测试副本让狗走出右边屏幕边，看窗口挪到右边那块、狗从左边走进来，再走回主屏幕（2026-11-26 在真机上 5/5）。拖过屏幕边要真鼠标拖，没写成脚本。

# 合养联网（M2 第一版）技术说明

规则见 PRD 3.1、3.2、3.2.1。这里写怎么实现的、东西放在哪、怎么测。

## 组成

| 位置 | 管什么 |
|---|---|

## 身份和数据

- 每台电脑用 Supabase 匿名登录拿一个身份，登录凭据、宠物码、组钥用系统加密（Windows DPAPI）存在 `userData/together.json`。
- 服务器只存宠物码的哈希、包好的组钥、加密后的纸条。客户端只能读自己组的数据；写一律走函数，函数里校验（只有狗所在那台能让它走、猜码限次、纸条限频）。
- 只能用公开密钥（Publishable / anon）。程序发现配置里是 Secret / service_role 会拒绝联网。

## 狗换地方的流程

1. 狗所在那台每分钟跑一次 `visit.decide()`（有纸条要送、有人呼唤时马上跑）。
2. 决定要走：主进程发 `depart` 给页面 → 页面播叼纸条、走出屏幕 → 走出去后回报 `together:departed`（带上肚子、心情）。
3. 主进程调 `start_travel`：服务器把 `pets.host` 换成对方，写 `pets.travel`。
4. 对方收到实时推送 → 发 `arrive` 给页面 → 从屏幕边走进来，带纸条的放到鼠标附近 → 调 `arrived`（纸条算送到）。
5. 读完纸条调 `read_note`。
6. 狗所在那台 3 分钟没动静（关机、断网）：在线的人里心动值最高的那台调 `start_travel(reason='reclaim')` 把它接过来。

实时推送偶尔会漏：订阅生效时、以及每 30 秒心跳时，都会从服务器重新拉一次。

## 测试

- 单元测试：`npm test`（规则、加密）。
- 冒烟测试：`npm run smoke`（单机，不联网）。
- 端到端：开两个测试副本当两个人（`PET_E2E=1`，各自 `--user-data-dir`、`--inspect`、`--remote-debugging-port`），脚本通过主进程的 `global.__petMain` 和页面的 `window.__rig` 驱动：建组 → 输码加入 → 同意 → 写纸条 → 狗叼过去 → 对方读 → 回信 → 呼唤规则。2026-11-26 跑过一次，23 项全过。
- 测试副本在桌面上是透明、点不到、不抢焦点的，不会多出一只狗；要用真鼠标拖它时设 `PET_TEST_VISIBLE=1`。
- 2026-11-26 名字改选填后又跑了一遍，25 项全过。实时推送：连接建好以后新人申请对方几乎立刻看到；刚建组、推送还没接通的那几秒可能漏，所以"一起养"窗口开着时每 5 秒拉一次，平时每 30 秒心跳时拉一次。

## 补完（2026-11-26）

数据库：`20261126c_m2_complete.sql`（主体）、`20261126d_fix_policy_recursion.sql`、`20261126e_kick_voids_code.sql`。三段都已在 Supabase 跑过；新建项目按顺序跑 a → b → c 就够了（d、e 的内容已经并进 c），跑过旧版 c 的补跑 d、e。都是只加不删，老客户端照旧能用。

| 功能 | 怎么做的 |
|---|---|
| 换邀请码 | 组钥不变，客户端换个新码把组钥重新包一遍（`rotate_code`）。邀请码本身用组钥加密存一份在 `pets.code_box`，组里每个人都看得到最新的码，服务器看不懂。一分钟最多换一次 |
| 退出 | `leave_pet`：这个人的所有电脑一起离开；狗在他那儿就交给组里最近在电脑前的人（按"到达"播动画）；最后一个人走了组就散了（宠物那一行删掉，成员、纸条跟着删）。退出的人桌面上回到单机的那只 |
| 请人离开 | `vote_kick`：两人组不行；除了被请的人其他人都同意才算，任何一人不同意作罢，被请的人看不到投票。通过的那一刻服务器先把旧码作废（`code_box='void'`、清掉换码限制），最后投票的那台马上换新码 |
| 申请作废 | 心跳时顺带把等了 3 天的加入申请、新电脑认领、投票作废 |
| 新电脑认领 | 输码先 `peek_pet` 看组里有谁；第一次来的 `join_pet`，换了电脑的 `claim_member` 认自己。设备表多了 `status`：认领时是 `pending`，组里有人 `approve_device` 才生效（被认领的本人在别的电脑上点"是我"也行）；组里只剩他自己时直接生效 |
| 几台电脑 | `pets.host_device` 记狗在哪台电脑上，只在那一台出现。另一台正在用、狗那台报"人不在"超过 90 秒（或 3 分钟没动静）时，用着的那台调 `follow_me` 把它接过来。你在另一台上用着时，原来那台不会因为"主人走开了"把它送走 |
| 碗＝呼唤小物件 | 狗不在时点碗，碗上冒气泡"它在小明那儿，在睡觉"，能看看它、叫它回来（在你另一台电脑上时是"叫它过来"）。"在干嘛"来自狗所在那台每 2 分钟传的状态 |
| 留它一次 | 被呼唤时你一分钟内和它玩过：狗身上冒气泡"让它去 / 再玩一会儿"，留 10 分钟（`keep_pet`），一次呼唤只能留一次，20 秒不选就让它去 |
| 远程看它 | "看看它"窗口开着时每分钟 `watch_pet` 续一次；狗所在那台每 4 秒截一张狗的小图（只截狗，240×180 以内的 PNG），用组钥加密后 `post_snapshot`；看的那边每 3 秒取一次。20 秒没新图就说"那边的电脑好像睡着了" |
| 远程喂 | `remote_feed`：整个组 10 分钟最多一次。狗所在那台碗倒满、碗上写是谁喂的；每次喂食只处理一回（记在本机） |
| 本机保险箱 | 改用异步系统加密（`a:` 开头）。老版本同步加密的（`e:`）启动时解开后换成异步；"狗在不在这儿"、心动值这几样不机密，不加密，程序一启动就能读 |

测试：`node tools/e2e/together-real.mjs`，四个看不见的测试副本当三个人（A 还有第二台电脑 A2），把上面都走一遍，最后所有人退出、组散掉，不留测试数据（匿名账号会留下）。不动鼠标，约 8 分钟。

读权限踩过的坑：设备表的读权限里直接查成员表，而成员表的读权限又查设备表，互相套住，读成员表报 infinite recursion（2026-11-26 上线后几分钟内发现，用 `pet_of()` 这个 security definer 小函数绕开）。以后写读权限，查别的表一律走 security definer 函数。

## 还没做

- 一人进多个组、同一台电脑上好几只（等 M4 有了毛色、品种变体再做，不然长得一样）。
- 匿名登录防刷：没加人机验证（要另外注册验证服务，还会打断"装上就能用"）。现在靠 Supabase 自带的按 IP 限匿名登录次数，加上服务器函数里的限次（试码、建组、纸条）。
- 日记只记在本机，组里几个人各记各的；以后可以加密同步。

# 桌面比格 · 产品需求 v0.1

> 整理自前期讨论。标"待定"的地方还没拍板，标"建议"的是讨论里提过、还没确认的做法。

## 1. 一句话

几个朋友（或情侣）合养一只桌面宠物。它同一时间只待在一个人的桌面上，会自己去别人家串门，也能被叫回来；养成按真实时间走，状态不显示数值，全靠它的动作和表情表现。

## 2. 目标用户

小范围的朋友、情侣，2 人起，可以多人。先在朋友之间用，代码放 GitHub。

- 主要做情侣还是朋友群：**待定**

## 3. 已经定下来的规则

### 3.1 合养

- 宠物不属于任何人，属于这个组。谁退出就是谁离开，宠物留在组里。
- 只能通过好友邀请加入。
- **不用注册、不用登录，宠物码就是钥匙**（2026-11-25 定）：每只宠物有一个固定的宠物码，和这只宠物绑定。在任何一台电脑上输入宠物码，就进入这只宠物的组，相当于登录。重装系统、换电脑、一个人有几台电脑，都是重新输一次宠物码。
- 第一次在某台电脑上输入时，选"我是新来的"或者从成员列表里选"我是谁"。这样喂食、纸条、互动记录才知道是谁做的。
  - **认领"我是谁"要有人确认**（2026-11-26 定）：组里有别人时，要一个人点同意（被认领的本人在别的电脑上点"是我"也行）；组里只剩他自己时，邀请码就是钥匙，直接生效。所以不做 4 位小密码。界面上"第一次来，加入"是主按钮，"以前就在这个组里，换了电脑？"收在小链接里，免得新朋友误点成别人。
- **界面上叫"邀请码"，名字选填**（2026-11-26 定）："一起养"窗口里只有"邀请朋友一起养"和"输入邀请码"两个按钮，不填名字、不放说明文字。没起名的人别人看到的是"TA"；进组以后点名单里的"你"随时可以起名、改名。程序自带联网配置，装上就能用，不用手动配任何文件。
- 宠物码由开盲盒的人创建宠物时生成，发给朋友就是邀请。输过一次的电脑会记住，之后不用再输。
- 建议的保护（因为宠物码泄露 = 谁都能进来）：
  - 码要够长，8 位以上字母数字混合，猜不到；服务端限制输错次数
  - 组里任何人都能"换个宠物码"：旧码立刻作废，已经进来的电脑不受影响（已做，2026-11-26；一分钟最多换一次）
  - 投票踢人后自动换码，被踢的人那几台电脑同时失效（已做：服务器在投票通过时就先把旧码作废，再由最后投票的那台换上新码）
  - ~~每个成员可以给自己设一个 4 位小密码~~：不做，改成认领要组里有人确认（见上）
- 踢人需要投票：除了被请的人，其他人都同意才算，任何一人不同意就作罢；被请的人看不到投票。
- **邀请新人要其他成员同意**（2026-11-26 定）：新人第一次输宠物码、选"我是新来的"以后，先进等待名单；组里其他成员都点了同意才算进组，任何一人都可以否决。这样宠物码就算泄露，陌生人也进不来。没人回应 **3 天**就作废（2026-11-26 定；新电脑认领、请人离开的投票也一样）。
- **两人组不能踢人，只能自己退出**（2026-11-26 定）。最后一个人也退出，组就散了，服务器上这个组的数据一起删掉。
- 建议：离开的人可以带走一本"回忆册"（它在你那儿的时间、截图、互相留的纸条）。
- **一个组最多 4 个人**（2026-11-26 定）。
- **一个人可以进好几个组**（2026-11-26 定）。这样同一台电脑上可能同时出现好几只宠物：它们是各走各的，还是会互相玩，**待定**。现在的程序一台电脑只能进一个组，好几只同屏等有了毛色、品种变体（M4）再做，不然几只长得一模一样。

### 3.2 串门和呼唤

- 同一时间只在一个成员的桌面上。
- 自己按"想念值"串门：谁越久没见到它，它越想去谁那儿。
- **心动值**（2026-11-26 定）：每个成员身上有一个看不见的心动值，狗在你那儿时你摸它、喂它、理它、给它写纸条都会慢慢涨，很久不互动会慢慢回落。心动值高的人那儿它更常去、待得更久。想念值和心动值一起决定它下一步去谁那儿、什么时候走。
- 成员可以呼唤它回来：有冷却；刚到一个人那儿有最短停留时间；对方正在和它玩时可以留它一会儿（只能留一次）。
- 呼唤入口：桌面角落一个常驻的小物件（食盆或口哨），它不在时显示它在谁那儿、在干嘛。**用的就是它的碗**（2026-11-26 做了）：它不在时点一下碗，碗上冒个气泡"它在小明那儿，在睡觉"，能看看它、叫它回来。
- 不在场的人可以打开小窗看它（"看看它"：几秒一张狗的小图，只截狗自己，截不到对方的桌面；加密后传）。**远程投喂做了**：整个组 10 分钟最多一次，只是把碗倒满，碗上写是谁喂的。
- 对方正在和它玩（一分钟内摸过、喂过、回应过）时被呼唤：狗身上冒气泡问"让它去 / 再玩一会儿"，留一次是 10 分钟，一次呼唤只能留一次；20 秒不选就让它去。
- 在线以"人在电脑前"为准（看系统空闲时间），不是"客户端开着"。人离开了，它会走。
- 同一个人多台电脑同时在线，它跟着最近有键鼠操作的那台。（已做：狗在你另一台电脑上、那台已经报"人不在"超过 90 秒时，你正在用的这台把它接过来；你在另一台上用着时，原来那台不会因为"主人走开了"把它送去别人那儿。）
- 它所在电脑断网、死机，服务端心跳超时后把它收回来，送回家或交给下一个在线的人。

### 3.2.1 带话纸条（2026-11-26 定）

- 纸条跟着狗走：写好以后，狗叼着去找收件人，送到放下、坐着等对方看。送到以后按串门的规矩在那边待着，不会马上跑回来；想它了可以呼唤。
- 收件人不在电脑前（键鼠 5 分钟没动，或者没开机）：狗先不出发，等对方回到电脑前再叼过去。写的人自己这时候不在也照样送。
- 狗正在收件人那儿时写的纸条：它会先回来拿（有纸条等着送，它回来得更快），再叼过去。
- 寄给谁：现在一个组就两个人，默认寄给另一个人；人多以后在纸条里用 @昵称 选收件人。
- 纸条用手写体（霞鹜文楷），信纸要好看。
- 纸条在本机加密后再上传，服务器上只有乱码；钥匙从宠物码派生，只有组里的人解得开。

### 3.3 盲盒

- 盲盒开出的是宠物本身，每个组开一次，不收钱。
- 稀有度只体现在外观（毛色、花纹），不影响能力。
- 建议：所有成员一起开（每人点一下才拆开）。
- 建议：先选猫还是狗，品种再随机。
- 第一批：狗和猫的若干品种，先做比格。

### 3.4 养成

- 按真实时间成长。
- 状态（饿、心情、困）不显示数值，只通过动作、表情、身体表现。程序内部有数值，但不给用户看。
- 先天条件做成"有得有失"的横向差异，不分好坏；有些特质藏着，养着养着才发现。
- 后天性格由几个成员一起影响。
- 进食贴近真实：碗里的粮一粒粒变少；胃有大小（先天），刚吃饱肚子鼓起来，几个小时后消下去；长期吃多才会变胖。
- 成长分七个阶段画（奶狗 2 个月、幼犬、小狗、少年、青年、成犬、老年 8 岁以上，见美术清单第 10 节），阶段内用骨骼比例每天微调；换阶段发生在它不在你面前的时候（串门、睡着），回来就"长大了"。
- **第一版（2026-11-26，规则在 `src/renderer/grow.js`）**：
  - 先天特质五样，每样有得有失：胃大小（胃大扛饿、一顿吃得多，但容易吃撑长胖；胃小饿得快）、贪吃（不饿也往碗边凑、吃得更撑 / 挑嘴）、精力（活泼的走得多爱邀玩但累得快 / 慵懒的爱趴着）、黏人（常来找你、没人理更委屈 / 独立）、好奇（爱闻地面 / 淡定）。大多数狗靠近一般，特别突出的约一成。合养的狗用宠物 id 定特质，组里每台电脑都一样；单机的狗第一次运行时随机定下。
  - 藏着、慢慢发现：要攒够观察（比如不饿时去碗边吃了 8 回）才在日记里写一句"不饿也老往碗边凑，是个小馋鬼"；一般的特质不写。
  - 后天性格两样：亲人（被摸、被回应慢慢变亲，求关注被晾着慢慢冷淡）、胆量（老被戳、拎得挣扎会胆小）。一天最多变一点点，不互动时一周回一半。性格和胖瘦跟着狗走（串门时带过去），所以是几个人一起养出来的。
  - 胖瘦：肚子长期九成二以上才长胖，一直撑着约五天胖满一档；饿着、走路慢慢瘦。胖了肚子线往下、往外圆一点；刚吃饱也会鼓一点。
  - 日记（托盘"它的日记"）：第一天、发现的特质、胖了瘦了、越来越亲人、来了一周一个月一百天、从谁那儿过来、谁托它带纸条、谁隔空喂了它。本机记，最多 500 条。
- 保留老年阶段（2026-11-25 定）：口鼻发白、动作慢一点。会不会生病、死亡：**待定**。所有人都不在时最多是饿了、生气，不会出事。

### 3.5 其他已定

- 平台：Windows 和 macOS。
- 不收钱。打工赚游戏币、商城买东西放二期。
- 暂时不做声音。
- 暂时不做内容审核（只在朋友间使用）。
- **从 GitHub 发布**（2026-11-27 定）：仓库公开，朋友在 Releases 页面下载安装包（exe）或免安装的压缩包（zip），两个都带联网配置，下载就能一起养。联网配置（Supabase 地址和公开密钥）也放进仓库：公开密钥本来就是给客户端用的、安装包里本来也带着，藏着没有用；放进仓库后从源码跑也能和朋友一起养，GitHub 云端打包也不用另外配密钥。推版本标签就由 GitHub 打包发布（公司网络会拦往外传程序文件，本机传不上去）。新版本只提醒、不自动更新：装好的版本每 12 小时问一次 GitHub，有新版本在托盘菜单放一条、每个版本只弹一次托盘提示，点了用浏览器打开下载页。不做静默自动更新，是因为没有代码签名，自动换程序文件风险大，也不符合"只在你点了的时候动系统"。

## 4. 宠物的表现

> 这里只列要点。每个姿势、动作、表情、行为的完整清单、现状和验收标准，见 `docs/pet-sop.md`。

### 4.1 姿势

溜达、闻地面、站着、坐下、趴下、睡觉（蜷着、会做梦）、邀你玩（前身趴低屁股撅高）。切换时平滑过渡。

### 4.2 单次动作

打哈欠、抖毛、伸懒腰（睡醒时自动做）、歪头、蹦一下。做完回到原来的姿势。

### 4.3 表情

平常、开心、好奇、委屈、犯困、吃惊、满足、讨吃的。由眼睛大小、上下眼皮、眉毛、舌头伸缩、下巴开合、耳朵前后、尾巴高低和摇法组合，可以叠在任何姿势上。

### 4.4 和人的互动

- 拖动：拎起来，腿垂下来晃；松手会掉下去，落地身子一沉。
- 点一下：吓一跳。
- 鼠标在头上来回划：摸摸，眯眼摇尾巴，冒小心心。
- 鼠标在附近晃：转头看你；你在它身后待久了它会转身。
- 喂一碗：走到碗边，前身压低，低头吃。
- 饿了：走到碗边坐下，看看碗再看看你，舔嘴。

### 4.5 不打扰

- 只有宠物身上可以点，其他地方的点击穿到桌面。
- **宠物待在桌面层，不在最顶层**（2026-11-25 定）：它在壁纸和桌面图标上面、所有程序窗口下面。你开着程序时窗口会盖住它，回到桌面（包括 Win+D）就能看到它。全屏游戏、放映自然会盖住它，不需要单独躲。完全被窗口盖住时停止绘制，几乎不占资源。
- 常驻时控制帧率和资源占用：窗口只盖底部一条，帧率按动静分档（30/24/8/5），走路约占一个核的 7%，静止约 3%。

## 5. 美术路线

- 2D 骨骼网格动画：AI 出整图 → 拆成零件 → 装骨骼和网格 → 程序驱动动作和表情。
- 放弃 3D：建模、绑骨、毛发的门槛太高，常驻桌面也太重。
- 每个基础姿势（侧面站、坐、趴、蜷睡、正面坐）单独画一套零件。
- 所有狗共用一套骨骼和动作，品种只换零件；猫另做一套骨骼。
- 美术需求和给 GPT 的提示词见美术需求清单（docs/art/asset-spec.md）。

## 6. 技术方案

- 客户端：Electron。透明、置顶、铺满工作区的窗口；默认鼠标点穿，鼠标移到宠物的不透明像素上时切成可点击。
- 渲染：WebGL，自写的 2D 骨骼蒙皮（线性混合），零件网格按透明度自动铺。
- 行为：状态机。姿势、单次动作、表情三层分开，参数平滑过渡；腿在坐、趴时自动找贴地的关节角度；耳朵是弹簧，跟头的加速度甩。
- 存档：本机 JSON（位置、肚子、碗里的粮、离开时间），离开期间按时间扣消化。
- 合养同步（第二阶段）：服务端为准。宠物位置、状态、事件都在服务端；客户端只负责表现。后端用 **Supabase**（2026-11-25 定）：账号、数据库、实时推送都用它现成的。
- 分发：GitHub Actions 打 Windows 和 Mac 安装包，放 Releases。没签名时 Windows 会提示 SmartScreen，Mac 首次要右键打开。
- 仓库里只放程序用的打包素材（`assets/beagle/<年龄>/rig-data.js`）；GPT 出的原图 `assets/beagle/hd-library/` 不进仓库（2026-11-25 定），本机保留，改了以后跑 `tools/build_hd.py` 重新打包。

## 8. 风险

- Mac 上的点穿和鼠标跟随要单独验证，需要一台 Mac 测试。
- 常驻桌面的资源占用，要持续盯着。
- AI 出零件的一致性和补画工作量，决定了品种能出多快。
- 串门的规则（想念值、呼唤、留人）要在真实朋友间试过才知道好不好玩。
